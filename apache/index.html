What happens, in order.

This is the actual order of operations inside the Lambda function — not a marketing sequence, the real one.

  1. Agent reports in

    The CloudWatch Agent on the instance publishes procstat_lookup_pid_count for httpd every 60 seconds, alongside CPU, memory, disk, and log data.

  2. Alarm evaluates

    When the pid count drops below 1 for one evaluation period — including when the process vanishes and no datapoint arrives at all — the alarm enters ALARM state.

  3. SNS fans out

    The alarm action publishes to a single SNS topic, which does two things at once: emails the raw alert, and invokes the remediation Lambda.

  4. Lambda runs the fix

    The function sends an SSM RunShellScript command: restart httpd, wait five seconds, check systemctl is-active.

  5. Lambda polls for the result

    Up to 20 attempts, 3 seconds apart, tolerating the brief window where the SSM agent hasn't registered the command yet.

  6. Outcome gets published

    Success publishes a resolved notice. A failed restart — or an SSM timeout — publishes an escalation with manual next steps instead.
